Desktop now opens an installed app in an `app-*` window of its own, behind the apps flag. The broker is the web's, run in the Ghostly window with one instance per app window, so the API and its limits are the same on both clients. `app_broker` answers the runner's `start` itself and passes every other request to the Ghostly window under the caller's window label, which is the only identity the broker reads. The broker's answer comes back as the result of `app_broker`, and its events go back to that window alone. Rust also checks 64 KiB and 50 requests a second before the broker sees a request. Three new commands, `app_open`, `app_post` and `app_close`, may be called by the Ghostly window only. An app granted `internet` gets the network runner's policy and a rule list that lets `https` and `wss` through and nothing else, so the Desktop row now says HTTPS and WSS only, as on the web. Measured on WKWebView (macOS 15.6) with the malicious app, under the full guard and the internet guard. Under the full guard nothing reached a listener: no fetch, image, socket, preconnect, `https` or `wss`, and the navigation lock refused the `about:blank` and `srcdoc` frames. Under the internet guard only the `https` fetch, the image and `wss` connected, and plain HTTP, preconnect and WebRTC still reached nothing. In both runs 109 other commands were refused. A request over 64 KiB got `too-large` and a burst of 60 requests got `too-fast`. Tauri's IPC object stays in app pages: Tauri defines it as a property that cannot be deleted or replaced, and answers every call through it. The threats table records this as a residual, with the gates that hold anyway. Desktop on Windows does not open apps until WebView2's equivalents are measured.
