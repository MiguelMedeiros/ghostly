The owner decided two things on 2026-10-06. First, network access becomes a phase 1 permission, `internet`. An app that declares it, and that the person approves at install, reaches HTTPS and WSS servers: fetch, sockets, images, media and fonts. It still gets no plain HTTP, no WebRTC, and no script, frames, workers, forms or navigation from anywhere. An app without it has no network, as before. The client runs a granted app in a second runner: the same page under the network runner's policy, `/app-frame-net.html` on the web. It picks that runner from the person's grant, never from the app. Adding `internet` in an update asks again, like any added permission. The manifest's permissions, the install lines, the threats table and the conformance line say so. A valid bundle vector asks for `internet`, and an app window on Desktop that has it gets a rule list that lets `http(s)` and `ws(s)` through. Second, Safari and the iPhone's web app are not restricted. In WebKit `<link rel=preconnect>` connects under every policy (measured), so their install screen says that in this browser an app can still contact other servers, and the threats table records it as a residual. The web runner also gained a hint guard as defence in depth. It leaves `<link>`, `iframe`, `frame`, `object` and `embed` out of the entry and out of every DOM way in, takes out any it sees, and withholds `document.write`. In WebKit none of the 19 ways measured connected with it, and every way probed did without it. It runs in the app's realm, so it is not counted as a stop.
