On Desktop a `file` answer no longer carries the file's bytes through the Ghostly window. The broker there still makes every check (the app's permission, the path, the 16 MiB a second), then answers with where the bytes lie in the client's own file storage; Rust reads them, checks their SHA-256 against the bundle's manifest, and hands them to the app's window as the raw result of its `app_broker` call. Before, each answer was base64 inside JSON on the Ghostly window's thread (32 ms per 16 MiB in Chromium, 7 ms in WebKitGTK), then about 22 MiB of JSON through Tauri's IPC, parsed in Rust and decoded again in the app's window. Where the broker cannot say where the bytes lie (the icon, kept in memory), the answer carries them in base64 as `bytes` as before. Nothing changes for an app: `ghostly.file(path)` answers an `ArrayBuffer` either way.
