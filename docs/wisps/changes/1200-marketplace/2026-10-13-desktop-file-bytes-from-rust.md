On Desktop a `file` answer no longer carries the file's bytes through the Ghostly window. The broker there still makes every check (the app's permission, the path, the 16 MiB a second), then answers with where the bytes lie in the client's own file storage; Rust reads them, checks their SHA-256 against the bundle's manifest, and answers the app's `app_broker` call with them in base64 as `bytes`, as before. Not raw: an app window cannot reach Tauri's `ipc://` (its CSP and rule list), so a raw result would be evaluated into it as a JSON list of numbers, about five times slower and twice the memory. Before, each answer was base64 inside JSON on the Ghostly window's thread (32 ms per 16 MiB in Chromium, 7 ms in WebKitGTK), then about 22 MiB of JSON through Tauri's IPC to Rust and back. Where the broker cannot say where the bytes lie (the icon, kept in memory), it carries them in base64 itself, as before. Nothing changes for an app: `ghostly.file(path)` answers an `ArrayBuffer` either way.
