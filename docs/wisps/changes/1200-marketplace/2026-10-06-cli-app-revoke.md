The CLI of release 1.2 also has `ghostly app revoke`: it signs a `ghostly-revoke/1` statement (digests, or every version up to a `sequence`, with an optional reason) with the app's publisher key, refuses any other key, and adds it to the canonical `ghostly-revoke.json` beside the bundle. Clients already check revocations, and without a tool a publisher could not make one; revocation is part of phase 1's security floor.
