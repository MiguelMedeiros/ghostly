An app's 5 MiB of storage in a scope now counts 128 bytes for each key beside the key's own bytes and its value's. Before, only the key and the value counted, while each key costs the device about 140 bytes more (the app's reference, the scope and the key again, in the row and its indexes): an app that kept one-byte values under short keys was told `full` only after some 800,000 keys, which took over 100 MiB for one app in one chat. With the 128 bytes a scope holds at most about 40,000 keys, and what it takes on the device stays near the 5 MiB the person is told. Nothing changes in what is stored, so a scope written before counts the same way; one that is past 5 MiB by the new count takes no new key, and still takes a delete or a write that does not grow it. `MINI_APP_LIMITS.storageRowBytes` carries the number for an app that plans its room.
