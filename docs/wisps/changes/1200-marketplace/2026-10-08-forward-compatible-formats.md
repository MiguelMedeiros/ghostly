A reader now ignores a key it does not know in a manifest (at its top and in `runtime`), a store index, a listing and a removal, instead of refusing the whole bundle or signed index (the owner's decision, 2026-10-08), so a later format can add an optional key without older clients refusing it. The signature and the digest still cover the bytes as they are, unknown keys included. Required keys, their types and bounds, `price` and `recovery`, a file entry's exact `{path, size, sha256}` and a copied revocation's exact keys hold as before, and a change an older client must not ignore still raises `ghostlyApp` or `ghostlyStore`. Writers stay strict: `ghostly app build`, `ghostly store sign` and the library's builders refuse an unknown key (`unknown-key`), so a misspelt key is never signed. `runtime.host` and `runtime.clients` are advisory: checked as the format says, never a reason to refuse an install or a run. The vectors move the unknown-key cases to the valid side and add a later key changed after signing, beside a missing or out-of-bounds required key, in a file entry and in a copied revocation.
