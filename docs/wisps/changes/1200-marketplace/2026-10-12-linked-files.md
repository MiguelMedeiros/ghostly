The owner accepted, as the direction, three additions for apps that work with a person's own files, which Cinema (an app that streams a person's films to a contact) found missing in phase 1. A new section, "The person's files through an app", designs them, with what Cinema measured today: **linked files** (a permission `files`; the client keeps a reference to files and folders the person picks, never a copy, and the app reads them in ranges of 1 MiB by an id it never chose), **a read lane** to the contact (a session capability `app-ranges/1`: the contact's app reads a file this side's app serves, in ranges, carried by the client with `files/3`'s flow control and as binary messages of kind `0x05` where `files/4` is on, outside `apps/1`'s 50 frames a second), and **sending ahead** (an app asks the client to send a linked file as a chat file, with the contact's consent as any file; `pf-offer` gains `app`, and the receiving app reads the stored file). Nothing is built; the section gives the order of work, and the decisions table, the phase 2 library and the later permissions point to it.
