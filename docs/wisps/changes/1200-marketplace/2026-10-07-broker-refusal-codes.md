The broker names why the client refused a storage write or a file read: `full` when a write would take the app past its 5 MiB in that scope, `bad-key` and `too-large` past the bounds of a key and a value, and `no-file` for a path the bundle does not have. Before, the client's own refusals reached the app as `failed`, the same word as a passing failure, so an app could not tell that it had to make room. Any other failure is still `failed`, and the client's own words never reach the app.
