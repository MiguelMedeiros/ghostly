On the web, the runner's `activity` now counts for the lock screen only while the client's page also has a transient activation (`navigator.userActivation.isActive`). The app runs in the runner's realm and can send `activity` itself, so with the focus alone as the check, an app left in front with no one there kept the lock away for as long as it ran. A tap or key in the frame activates the page around it too (HTML § user activation), and no script can; this was checked in Chromium and WebKitGTK. A browser without the API keeps the focus check alone. Desktop is unchanged: no activation reaches the client's window there.
