Read lane serves last until the app closes, not one session: a new session in place of the old one (a transport switch, a resume, a re-dial), across which the apps are held, keeps every serve id the app gave out, so the contact reads the same id again on the next session. Before, the serves ended there while the app heard only `open` again and its header still said it shared a file, and the contact's read got `not-served`. Requests in flight still end with the session (`offline`). A serve ends with `unserve`, when either side closes the app (a held app the next session does not take back within the 10 seconds included), or when the link stops for good. No frame changes.
