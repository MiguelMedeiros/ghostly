A request whose arguments hold a lone surrogate (half of a UTF-16 surrogate pair, in a string or a member name) is now refused with `bad-request` on every client: the web broker took it, while on Desktop Tauri's JSON refused it before the broker saw it and the app got `failed`. The Desktop runner refuses it before it leaves the window, as it does arguments that are not JSON. An answer or event holding one (a value stored before, or restored from a backup) reaches the app with U+FFFD in its place on every client: on Desktop it used to fail on its way to the app window without a word, and the app waited a minute for `failed`.
