Settled the details the bundle format left open, as built in `packages/core` with its test vectors. The manifest table gives exact bounds (SemVer, `sequence` from 1 to 2^53 - 1, lengths in code points, one-line texts, `runtime.host` as `>=MAJOR.MINOR[.PATCH]`, a light SPDX grammar, at most 8 `sources`), every URL is https without a user or password and on jsDelivr only at a full commit, screenshots are the files under `screenshots/`, and keys, hashes and signatures must encode back to the same text. The signature statement is canonical with exactly `alg`, `key` and `sig`, its key is the publisher, and signatures verify as RFC 8032 writes it. A bundle is read in a fixed order with a refusal code at each step. A revocation has an exact shape (`digests` or `upTo`, an optional reason) and travels as `{statement, signature}`. A store index has exact fields and bounds, Unix-second times, a refusal for equivocation and for another store key, and a revocation that does not verify refuses it. Publisher proofs and `ghostly-publisher/1` move after phase 1: a phase 1 manifest's `proofs` must be empty. The Test vectors section names the segment encoding of bundle bytes and the fixed clock.
