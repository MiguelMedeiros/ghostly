The read lane's calls are typed in `@ghostlytools/sdk/app`: `files.serve(id)` answers a serve id and `files.unserve(serveId)` ends it; `remote.read(serveId, {offset, length})` (at most `remoteReadBytes`, 1 MiB) and `remote.stat(serveId)` on the contact's side, with `ghostly.remote` absent in a client without the lane. The broker gains the code `not-served`; `files.serve` is refused with `peer-closed` while the contact cannot read and with `gone` for an id not kept; `remote.read` answers count in the app's file budget. No client answers them yet.
