The two host candidates an `_rtc` signal carries are chosen, not the first two the browser lists: those a server reflexive candidate was gathered from or on a global IPv4 address (which gets no reflexive candidate) first, those marked costly (`network-cost` 50 or more: a VPN) last, the browser's order otherwise. On a Mac with two VM bridges, Ethernet, Wi-Fi, Tailscale and a VPN, Chromium (with the page allowed the microphone, so it gathers on every interface) lists the two bridges first: every data link's signal carried those two addresses, which exist on that Mac only, and never its Wi-Fi or Ethernet address. A contact on the same network was then reached only through the public address, which needs a router that sends such a packet back in; a call's signal already chose its candidates (`pickCallCandidates`). No wire change: the same `h,<address>,<port>` entries, other ones.
