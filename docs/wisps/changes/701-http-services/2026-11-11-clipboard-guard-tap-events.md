On the web, the clipboard guard of a contact's app also lets a copy through in a `dblclick` and a `contextmenu` of the person's, and in a trusted `submit` or `change` that the person's input sets off (its default action, before the first callback the guard queues at any input runs; the rendering step right after the input too, whose animation frame callbacks the app asked for before it run ahead of the guard's message and task), so a form, a checkbox, a double click or the app's own context menu copies on the person's tap ([On the web](../../701-http-services.md#on-the-web)). A `submit` or `change` the app's script fires itself outside an input, or later (a timer, a promise, a message, an animation frame it asks for at or after the input), still does not.
