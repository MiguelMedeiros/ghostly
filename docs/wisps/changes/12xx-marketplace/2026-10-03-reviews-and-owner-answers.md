Revised after a security review, a product review that tested the sandbox, and the owner's answers to the six open questions. The owner's decisions are recorded (free only, one default store repository signed offline by the owner, chat-sent apps installable with a warning, the extension built with a fallback, no network for apps, the default index as a signed file in the same repository) and the open questions replaced by three new ones. The runner now talks over one MessageChannel port, tears an app down on a second load, deletes the WebRTC constructors before app code, refuses to start outside a null-origin frame or an `app-*` window, and has `frame-ancestors 'self'` on a location of its own, with `frame-src 'self'` on the parent; Desktop gets one `app_broker` command for `app-*` windows with identity from the label, navigation blocked and new windows denied without the system browser; the broker tells apps apart by port and keeps storage per app and per chat; the receiver enforces `apps/1` limits. A package is one `.ghostlyapp` bundle with a single self-contained HTML entry, a canonical manifest and no trailing bytes, committed to the repository and fetched without api.github.com; every signed statement has a prefix; key rotation and the recovery key are reserved for phase 2; chat cards show their own data and fetch only on Install from allowlisted hosts; cards lead with the verified proof and an 80-bit fingerprint, or "Unknown publisher"; catalogs and indexers become one "Stores" list of signed files; the publisher CLI is `ghostly app init | publish` and `ghostly catalog submit`; no store is polled until an app is installed; themes are deferred; games are covered (turn-based with commit-reveal and light versus games such as Tetris and Snake on ordered `apps/1` in phase 1, fast real-time in phase 2); a bot on the headless CLI can serve an app's `apps/1` messages in phase 2, and the agent console is chosen as a built-in screen rather than an app; the phase 2 licence key has a salt, and every derivation from the DID seed is listed. A closing check then fixed the runner's start (it says `writing` on the port before `document.open`, and the parent accepts exactly one load after it), let only curated stores clear "Unknown publisher" and "Not in any of your stores" (an indexed listing shows "Found by <index>"), and settled the builder decisions: the broker's messages and the whole `ghostly.*` API, `apps/1` open, close and version frames, a chat app id keyed on both participation keys, the store signature file, where revocations live, `listing.json` and the crawler's input, storage, export, backups and handoff, and the encodings; the coordinator's answers to the last three questions are recorded and no question is left open.
