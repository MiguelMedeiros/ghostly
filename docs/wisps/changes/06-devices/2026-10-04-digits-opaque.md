Brought in line with what shipped. The enrollment digits take the first 32 bits of their hash, not 20: modulo a million, 20 bits make the values under 48,576 twice as likely as the rest, and 32 bits bring that down to about one part in 4,295. The password proof of a pull is OPAQUE (RFC 9807) with ristretto255 and Argon2id, through the reviewed `opaque-ke` crate compiled to WebAssembly, not SPAKE2+ (RFC 9383) with PBKDF2-SHA256: no maintained, reviewed JavaScript implementation of SPAKE2+ exists, OPAQUE is augmented in the same way with the same three messages, and Argon2id is memory-hard. OPAQUE takes no session context, so frame 3 of `handoff-pake` carries an HMAC of the context under the shared key, which the active device checks, and the key still goes into the stream key. The note that the protocol was a candidate is replaced by these reasons.
