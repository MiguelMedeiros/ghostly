Installing the staged state: deleting the old namespace after a take never deletes the registry of profiles. On a Desktop in a space of its own (`GHOSTLY_PROFILE`), the first profile's namespace is the space's name and its keys share a prefix with the registry, so the take deleted the pointer it had just written and the app opened the old, empty namespace. The staged record now keeps the profile's own database name (`home`), and an app that finds a profile with no pointer and no record under its own name points it again at the namespace whose record names it. The app checks that the pointer write took effect before it reloads. Found by the Linux Desktop bug hunt (3 of 3 handoffs to Linux ended in an empty profile).
