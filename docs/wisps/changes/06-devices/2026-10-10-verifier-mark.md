The turn record now states which password proof verifier the profile has: every ordinary record's `instance` is three random bytes, the marker `0x67 0x76` and a three-byte mark of the verifier, written again as soon as the verifier changes. The record's version and layout are unchanged, so an app from before goes on reading the turn; its own records state nothing. A standby with a frozen copy compares the mark with its own verifier's before a forced takeover and refuses when they differ: the lock password was changed after it last had the profile, and Use here moves the profile with the new one. A device replaced by a takeover is not held to it. The verifier is now replaced only when the lock password changes: typed again unchanged (Add a device), the stored one is kept; and the verifier beside the active device's state is always the one in the profile's settings, none when they hold none.
