Revised after a security review and a product review, so that phase 1 can be built from it. The device-set secret is the authority (an unknown signer is accepted on a takeover without a release, and a backup holder holds it), the first one is derived from the DID key, and device links are derived from it and the two device keys. The turn record has a fixed binary body, a neutral label, a sequence number that folds in the author's slot, byte-identical re-puts, conditional puts that are never repeated without their condition, a read of every source, an instance id that exposes cloned storage, and a tombstone that only serves honest devices. The guarantee now covers the normal handoff only, with strict durable writes and a taker that starts after its turn is read back. Added: the gate in front of the engine start and a device-link-only mode; enrollment with a new invite version, one session per invite and digits after the inviter's proof; a required lock password and a rate-limited password proof for a pull; a copy in two passes with files skipped by digest; frame shapes, the canonical digest, a state by event table, a crash-recovery matrix and the list of tests. Forced takeover raises an exact list of counters with a floor for groups, keeps admin work off and never broadcasts saved signed bytes. Wallets follow one single-writer rule behind a fresh turn read; Bark, Fedimint, USDT and pinned LND stay on their home device in phase 1, with coin expiry shown and enforced. Removing a device, the push target that survives a switch, the standby that never rings and "Move to" from the active device are in phase 1; the prepared handoff, the CLI commands and incremental copies are later phases. The experiments' results and what is still to measure are listed.
