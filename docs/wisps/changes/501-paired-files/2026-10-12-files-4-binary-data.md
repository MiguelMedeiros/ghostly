`files/4`: a file's bytes travel as one binary message of the session (kind `0x04`, the id, an 8-byte offset, up to 16 KiB of data) instead of base64url text in a `pf-data` frame, which cost a third more than the file on every transport. It is a session capability beside `files/3`, offered only on a session whose adapter carries binary messages (WebRTC today), and every other frame and rule is `files/3`'s. An app that lists it takes data in either form; with any other app, files stay on `files/3`.
