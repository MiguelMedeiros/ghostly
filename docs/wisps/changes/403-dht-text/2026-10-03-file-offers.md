A file's offer rides the floor while the chat is not live: the signed body's sixteenth element `[wireId, size, mime, meta]` says the envelope's text is a file's name, under the id the first 16 bytes of SHA-256 of `ghostly-file/1:<wireId>` give, to a contact whose capability record lists `dht-file/1`. It takes the floor's one slot in the order things were written, so a text written after a file no longer reaches the contact before it; the bytes still go on the live session, whose offer takes the bubble over. A file deleted before it went live is said cancelled (`pf-abort`) on the next session. Readers from before take no such envelope, since they are never sent one.
