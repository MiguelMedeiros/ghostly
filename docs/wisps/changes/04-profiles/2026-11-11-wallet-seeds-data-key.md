The wallets follow slice 2: with the data key slot empty, every wallet's seed (Ark, Bark, Spark and its API key, Fedimint, USDT) and the provider wallets' secrets are sealed as before (version 1, a device key beside them); with it set, as version 2 bound to their wallet's record and field, and the record keeps no `deviceKey`. An Ark or USDT wallet that opens by itself says so with `automatic` instead; one sealed with a password the person chose keeps that password, and with the key set that sealed seed is itself inside a version 2 field. Once the migration has ended, a seed sealed with a device key or a password alone is refused. No client sets the key yet (Encrypted profile).
