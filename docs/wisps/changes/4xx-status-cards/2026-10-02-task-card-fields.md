A task card may say more, in four optional fields an older app ignores: `pr.state` (`draft`, `open`, `merged`, `closed`) and `pr.checks` (`passing`, `failing`, `pending`) on its pull request, `tags` (up to 3 labels of 24 characters) and `parent` (the id of another task of the same sender in the same chat). No status was added: a reader drops a card with a status it does not know. A reader leaves out what does not hold, a sender is refused it, and the fallback text says them. The Tasks board uses them: a Review column for a task whose pull request is open, a checks mark on the pull request's chip, tag chips and a filter by tag, and a task's parts stacked under it with a summary.
