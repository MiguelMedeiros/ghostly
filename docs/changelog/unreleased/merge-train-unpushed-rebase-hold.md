- The merge train leaves a lone pull request alone when it was put on hold, turned into a draft or got a running or "changes needed" review after the push of the train's second rebase of it failed, and pushes that rebase once the hold ends. Before, the next run pushed it anyway: a held branch was force-pushed, and since a review's hold ends on a new head, the train's own push ended it and the pull request could land with changes asked of it. A lone pull request held or a draft while it waits also keeps the train's mark in its position comment now: it lost it, so after the hold a red first rebase got no second run and no `queue:failed`, and waited for good. Once its hold ends and it flies again, that mark no longer says it is parked, so another parked one whose hold ends later does not take its place in flight.
