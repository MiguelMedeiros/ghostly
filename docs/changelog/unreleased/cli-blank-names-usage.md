- `ghostly group create <name...>`, `group rename <group> <name...>` and `service add <name>` given a name with nothing that shows (spaces only, a zero-width space, only invisible or direction-changing characters), and `invite create --label`, `invite join --label` and `chat rename <chat> <name...>` given one with nothing that shows that is not blank, now refuse it before the profile opens as a usage error (exit 2) naming the argument or option: `<name> needs a character that shows`, `--label needs a character that shows (an empty one gives back the contact's own)`. Before, a one-shot made and opened the profile and went online first (0.4 to 1.3 s), then the engine refused it as `bad_request` (exit 1) in words that named no argument (`A group's name needs a character that shows`). The rule is the engine's own (a name as it is stored, cleaned). `""` is still the missing `<name>` (exit 2); a blank `--label` or `chat rename` name is still no label (the chat shows the name the contact gave itself), exit 0. The socket's `group.create`, `group.rename`, `service.add`, `invite.create`, `invite.join` and `chat.rename` answer as before (`bad_request`).
